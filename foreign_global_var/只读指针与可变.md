## 用具体图示理解

假设内存布局是这样：

**`static mut` 控制的是左边（0x1000 处的变量）：**

```

**`*const c_char` 控制的是右边（0x2000 处的内容）：**

```

## 和 C 语言的对应关系

这在 C 里的写法是：
```c
// C 代码里的 rl_prompt 声明（readline 库实际就是这样声明的）
extern const char *rl_prompt;
```

翻译成 Rust 就是：

| C 声明 | Rust 对应 | 含义 |
|--------|-----------|------|
| `const char *rl_prompt` | `rl_prompt: *const c_char` | 指针指向**只读**字符 |
| （可以给 rl_prompt 赋值） | `static mut` | 变量本身是**可变**的 |

> readline 库的设计就是：你可以**更换** prompt 字符串（改变指向），但不应该**修改** prompt 字符串的内容（因为 readline 内部可能直接用这个指针，改内容会导致 UB）。

---

## 对比：如果改成 `*mut` 会怎样？

```rust
static mut rl_prompt: *mut libc::c_char;  // 这样写也是能编译的
```

区别是：
- `*const c_char` → 你**告诉 Rust**：我不会通过这个指针去修改内容，请帮我监督
- `*mut c_char` → 你**告诉 Rust**：我可能会通过这个指针修改内容，给我全部权限

但 readline 内部实际用的是 `const char *`，所以用 `*const` 更准确，也更安全（能避免一些误操作）。

## 总结：一句话记忆

> **`static mut` 管的是"变量本身能不能改指向"，`*const`/`*mut` 管的是"能不能通过指针改内容"。这是两个独立的维度，不矛盾。**

类似的，你还会见到这四种组合，都是合法的：

| Rust 写法 | 含义 |
|-----------|------|
| `static S: *const T` | 变量不可变，指向的内容也不可变 |
| `static S: *mut T` | 变量不可变，但能通过指针改内容 |
| `static mut S: *const T` | **你的代码**：能改变量指向，但不能改内容 |
| `static mut S: *mut T` | 既能改变量指向，也能改内容 |
